## การไหลของข้อมูล

นักเรียน `run.html` → `POST /api/runs {action:'submit'}` → Cloudflare ตรวจรูปแบบภาพ/ขนาด → Apps Script `run_submit` ตรวจประเภท (personal/event) ระยะ เพซ วันที่ รายการซ้ำ และมีชื่อใน `Main_2569` → อัปโหลดภาพเข้าโฟลเดอร์ Drive รายคน → เพิ่มแถว `Runs_2569` สถานะ `pending`

ผู้ตรวจ `run-admin.html` (ส่ง `X-Admin-Key`) → `review` → Apps Script คิดชั่วโมงจาก `kmPerHour` แล้วตัดด้วยเพดานต่อวัน/ต่อภาค **จากรายการที่อนุมัติแล้ว ณ เวลานั้น** ภายใต้ `LockService` → บันทึก `approved` + ชม.ที่ได้จริง + เหตุผลการตัด

ชั่วโมงหมวด 10 **ไม่เขียนลง `Main_2569`** เพราะสูตรคอลัมน์หมวด = 6 + หมวด จะชนคอลัมน์ 16 (ยอดรวม) ยอดรวมที่แสดงในหน้า run = ชม.หมวด 1–9 จาก `getStudentSummary` + ชม.วิ่งที่อนุมัติ

## ความปลอดภัย

- `RUN_GATEWAY_KEY` (Cloudflare secret = Script Property) — กันคนยิง Apps Script URL ตรง ถ้าไม่ตั้ง → ปฏิเสธทั้งหมด
- `RUN_ADMIN_KEY` (Cloudflare secret) — สิทธิ์ตรวจ/บันทึกสมรรถภาพ/แก้กติกา เทียบแบบ constant-time; หน้าผู้ตรวจเก็บใน `sessionStorage` เท่านั้น
- การส่งผลวิ่งของนักเรียนยังยืนยันตัวตนจาก session ฝั่งเบราว์เซอร์ (เหมือนระบบความดีเดิม) — ความเสี่ยงที่เหลือคือส่งแทนคนอื่นได้ แต่ทุกรายการต้องผ่านผู้ตรวจที่เห็นภาพหลักฐานก่อนนับผล
- GET รายคนตัด `gps` ออกก่อนส่งกลับ; โหมด GPS ไม่ส่งพิกัดดิบ ส่งเพียงสรุปและภาพเส้นทาง

## ติดตั้ง (เจ้าของระบบทำ)

1. **Apps Script**: เพิ่มไฟล์ `RunTracker.gs` และอัปเดต `Code.gs` (hook ใน `doPost`) → Project Settings → Script Properties เพิ่ม `RUN_GATEWAY_KEY` = สุ่มยาว ≥ 32 ตัวอักษร → Deploy → **Manage deployments → แก้ deployment เดิม → New version** (URL เดิมไม่เปลี่ยน)
2. **Cloudflare Pages** (`rtafnc-gooddeeds`) → Settings → Variables and Secrets (Production, Encrypt):
   - `RUN_GATEWAY_KEY` = ค่าเดียวกับข้อ 1
   - `RUN_ADMIN_KEY` = รหัสผู้ตรวจ (สุ่มยาว ≥ 20 ตัวอักษร แจกเฉพาะผู้ตรวจ)
   - `GAS_URL` มีอยู่แล้ว
3. ทดสอบ: `node scripts/check-syntax.cjs && node --test tests/*.test.cjs`
4. Deploy: `npx wrangler pages deploy frontend --project-name rtafnc-gooddeeds --branch main`
5. ตรวจหลัง deploy: เปิด `/run.html` ด้วยบัญชีนักเรียนทดสอบ → ส่ง 1 รายการ (ทำเครื่องหมาย SYSTEM TEST ในหมายเหตุผู้ตรวจตอนไม่อนุมัติ) → เปิด `/run-admin.html` → ไม่อนุมัติพร้อมเหตุผล "SYSTEM TEST"

ชีต `Runs_2569`, `Fitness_2569`, `Run_Settings` ถูกสร้างอัตโนมัติเมื่อมีการเรียกครั้งแรก

## กติกาค่าเริ่มต้น (ข้อเสนอ รอวิทยาลัยอนุมัติ — แก้ได้ที่หน้าผู้ตรวจ)

| | 10.1 วิ่งส่วนตัว | 10.2 งานวิ่ง/วิ่งการกุศล |
| --- | --- | --- |
| ชั่วโมง | 10 กม. = 1 ชม. ปัดลง 0.5 | 2 ชม./งาน (≥ 5 กม.) |
| เพดาน | 1 ชม./วัน · 3 ชม./ภาค · 6 ชม./ปี (ชั้นปี 4: 4) | 2 งาน/ภาค |
| เงื่อนไข | เพซ ≤ 10 นาที/กม. จึงได้ชั่วโมง | ต้องระบุชื่องาน + ภาพเบอร์วิ่ง/ใบประกาศ |

ทั้งสองแบบ: 0.5–42.2 กม./ครั้ง · เพซ 3–20 นาที/กม. · ส่งย้อนหลัง ≤ 7 วัน · ภาค 1 = 1 ก.ค.–30 พ.ย., ภาค 2 = 1 ธ.ค.–30 มิ.ย. · ชั้นปี = ปีการศึกษา 2 หลัก − รุ่น + 1
เพดานของ 10.1 และ 10.2 แยกกัน ⇒ สูงสุด 7 ชม./ภาค เหตุผลของตัวเลขอยู่ใน SOP-GD-06 ข้อ ค.
