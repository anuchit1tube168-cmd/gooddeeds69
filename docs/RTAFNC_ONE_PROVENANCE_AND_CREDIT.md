# RTAFNC ONE — Provenance & Credit Policy

## User-facing system credit
For RTAFNC ONE modules developed/adapted for current college use, the standard visible maintainer/developer line is:

`ผปค.วพอ.พอ. ร.อ.อนุชิต ทำจะดี ผู้พัฒนา`

This line may replace obsolete demo/template maintainer text in the RTAFNC ONE runtime UI.

## Internal provenance must be preserved
Removing a visible template/demo credit must not falsify authorship of third-party source code or assets. For every imported project, keep an internal provenance record with:
- original project/file title
- source Drive/GitHub identifier
- created/modified timestamps
- original author/credit text when present
- license or usage terms when present
- imported/adapted date
- modifications made for RTAFNC ONE

## Rules
- Never rewrite the original Source Vault solely to change credit.
- Runtime copies may use the standard RTAFNC ONE developer line after adaptation.
- Third-party copyright/license notices that legally require preservation remain in source/internal notices as required.
- If ownership/license is unclear, mark `CREDIT_REVIEW_REQUIRED` and do not represent the source as original work.
- Demo/template names that are not required legal notices may be removed from user-facing UI in the adapted runtime, while source provenance remains internal.

## Goal
A clean official RTAFNC ONE interface without confusing legacy/demo branding, while maintaining a defensible audit trail of where imported components originated.
